# منظومة متابعة أنشطة مراكز تنمية الأسرة والطفولة

نسخة كاملة (Full-stack) من النموذج الأولي: **Node.js + Express** للخادم، و**PostgreSQL** لقاعدة البيانات، وواجهة HTML/JS بنفس تصميم النموذج.

## ما الذي تغيّر عن النموذج الأولي

| النموذج الأولي | النسخة الكاملة |
|---|---|
| الدخول بحساب Claude | حسابات خاصة بالمنظومة (بريد + كلمة مرور) ودوران: **إدارة المشروع** و**مؤسسة مشغلة** |
| المدير = من يملك صلاحية تعديل الصفحة | تبويب **الحسابات** لإنشاء حسابات المؤسسات وإيقافها وتغيير كلمات المرور |
| البيانات في قاعدة Claude | جداول SQL في PostgreSQL (انظر `src/db/schema.sql`) |
| الصور كنصوص base64 داخل القاعدة | ملفات JPEG في مجلد `uploads/`، والقاعدة تحفظ مساراتها فقط |
| فحص التكرار في المتصفح فقط | الفحص في المتصفح **و** في الخادم، مع قيد `UNIQUE` في القاعدة |
| الحفظ نشاطًا نشاطًا | الدفعة كلها تُحفظ في معاملة واحدة (كلها أو لا شيء) |
| كل مستخدم يحمّل كل البيانات | حساب المؤسسة لا يرى إلا أنشطة وصور مؤسسته |

### الدورة المستندية والاعتمادات
كل ما ترسله المؤسسة يمر على إدارة المشروع للاعتماد، ولكل مستند **سجل زمني** (من أرسل، ومن اعتمد أو أعاد، ومتى، وبأي ملاحظات):

| المستند | دورة الاعتماد |
|---|---|
| الأنشطة المنفذة | قيد المراجعة ← معتمد، أو معاد للتعديل (لكل نشاط على حدة) ← تعدّله المؤسسة فيعود للمراجعة |
| الخطة الشهرية | مسودة ← مرسلة (تُقفل) ← معتمدة بكود، أو معادة للتعديل بملاحظات |
| التقارير | المؤسسة تطلب اعتماد تقرير مؤسستها ← الإدارة تعتمده بكود أو تعيده. الإدارة تُصدر التقارير القومية وملف التوثيق مباشرة بكود |

- تبويب **المهام والاعتمادات**: للإدارة كل ما ينتظر اعتمادها (اعتماد/إعادة بضغطة، مع تحديد أنشطة بعينها)، وللمؤسسة ما يحتاج تعديلًا منها وما هو قيد المراجعة، مع متابعة مراكزها هذا الشهر.
- **جرس التنبيهات** أعلى الصفحة: تنبيه فوري عند كل إرسال أو اعتماد أو إعادة، وتذكيرات (خطة الشهر القادم لم تُرسل، مراكز أقل من الحد الأدنى). يتحدث تلقائيًا كل ٣٠ ثانية.
- التقارير وملف التوثيق تشمل **الأنشطة المعتمدة فقط**.

### التقارير الرسمية: PDF و Word بكود اعتماد
- كل تقرير أو خطة يُنزّل بصيغة **PDF** أو **Word (.docx)** أو HTML، بهوية الموقع (الشعارات، الألوان، الخطوط).
- المستند المعتمد يحمل **كود اعتماد** مثل `FCDC-R2611-7KQ4-9XZT` في تذييل كل صفحة، وختم اعتماد برمز **QR**.
- أي شخص يتحقق من المستند بمسح الرمز أو بفتح `/verify` وإدخال الكود، فيرى بيانات الاعتماد والأرقام الرئيسية وقت الاعتماد.
- النسخة غير المعتمدة تُنزّل بعلامة «مسودة غير معتمدة».
- النسخة المعتمدة تُحفظ في قاعدة البيانات كما اعتُمدت، فإعادة تنزيلها لاحقًا تعطي نفس المحتوى.
- ملف PDF يُولَّد على الخادم بمتصفح Chrome (موجود داخل صورة Docker). خارج Docker يُكتشف Chrome أو Edge تلقائيًا على Windows وMac، أو اضبط `CHROME_PATH`.
- اضبط `PUBLIC_URL` على رابط الموقع الحقيقي (مثل `https://fcdc.example.org`) حتى يفتح رمز QR من أي هاتف.

### تجربة حسابين في نفس الوقت
المتصفح الواحد يحفظ جلسة دخول واحدة، فلو دخلت بحساب المؤسسة ثم بحساب المدير في نفس المتصفح، **يحل الحساب الثاني محل الأول في كل التبويبات**. لتجربة الدورة كاملة افتح حساب المؤسسة في نافذة عادية وحساب المدير في **نافذة تصفح خفي (Incognito)** أو في متصفح آخر.

### الخطة الشهرية (محضر اجتماع ٧ أكتوبر ٢٠٢٦)
- **المحاور العشرة** أصبحت هي تصنيف الأنشطة المسجلة وبنود الخطة (الأنواع القديمة تُخفى ولا تُحذف، فتبقى الأنشطة المسجلة بها كما هي).
- تبويب **الخطة الشهرية**: خطة مستقلة لكل مركز في كل شهر، لكل نشاط: الاسم، المحور، الفئة المستهدفة، العدد المتوقع، التاريخ والتوقيت، الجهة المنفذة/الشريكة، المسؤول عن التنفيذ.
- ضوابط يتحقق منها الخادم: التوقيت داخل الفترة التشغيلية ٧:٣٠ ص – ٥:٠٠ م، لا أنشطة يومي الجمعة والسبت (`weekendDays` في `src/config.js`)، التاريخ داخل شهر الخطة، ٣ أنشطة على الأقل قبل الإرسال، لا تكرار.
- تنبيهات أثناء الإعداد: أسابيع بلا أنشطة، تداخل التوقيتات، مناسبات الشهر غير المدرجة، والمحاور المغطاة. المناسبات الرسمية والأيام العالمية الثابتة تُقترح تلقائيًا (القائمة في `src/db/seed-data.js`)، والهجرية تُضاف يدويًا.
- دورة الاعتماد: مسودة ← مرسلة للاعتماد (تُقفل أمام المؤسسة) ← معتمدة، أو معادة للتعديل مع ملاحظات الإدارة.
- تنزيل الخطة كملف للطباعة (A4 أفقي) بجدول الأنشطة والتوزيع على المحاور وخانات التوقيع.
- لوحة المتابعة تعرض عمود **خطة الشهر**، والتقارير تتضمن قسم **الالتزام بالخطة الشهرية** (المخطط مقابل المنفذ).

قواعد العمل كما هي: ٣ أنشطة على الأقل في كل تسجيل، لا نشاط مكرر (نفس العنوان في نفس المركز خلال الشهر، أو نفس التاريخ والنوع وعدد الحضور)، حتى ٤ صور لكل نشاط، لا تواريخ مستقبلية.

## التشغيل

### الطريقة الأسهل: Docker
```bash
docker compose up -d
```
افتح http://localhost:3000 وادخل بـ `admin@example.com` / `change-me-now` ثم غيّر كلمة المرور فورًا.

#### لو Docker مش شغال
| العَرَض | الحل |
|---|---|
| `docker: command not found` أو `Cannot connect to the Docker daemon` | ثبّت Docker Desktop وافتحه واستنّى لحد ما يقول Running، ثم أعد الأمر |
| `docker-compose: command not found` | الإصدارات الحديثة: `docker compose` (بمسافة). القديمة: ثبّت `docker-compose` |
| `port is already allocated` / `address already in use` | المنفذ 3000 مستخدم: غيّر `"3000:3000"` في `docker-compose.yml` إلى `"8080:3000"` وافتح http://localhost:8080 |
| فشل `npm ci` أثناء البناء | تأكد من الاتصال بالإنترنت، ثم `docker compose build --no-cache` |
| بيرجعك لصفحة الدخول بعد الدخول | تأكد إنك على آخر نسخة (تم إصلاحه) ثم `docker compose up -d --build` |
| غيّرت بيانات المدير ومش بتشتغل | حساب المدير يُنشأ أول مرة فقط. للبدء من الصفر: `docker compose down -v` ثم `docker compose up -d --build` (يمسح كل البيانات) |

لمعرفة سبب أي مشكلة: `docker compose logs app`

### بدون Docker
المتطلبات: Node.js 18+ و PostgreSQL 13+.
```bash
npm install
cp .env.example .env        # عدّل DATABASE_URL و JWT_SECRET وبيانات المدير
createdb fcdc               # أو أنشئ القاعدة من pgAdmin
npm run db:init             # ينشئ الجداول ويضيف المؤسسات والمراكز وحساب المدير
npm start
```
`npm run db:init` آمن للتكرار: يحدّث بيانات المؤسسات والمراكز من `src/db/seed-data.js` دون حذف أي أنشطة.

### الاختبارات
```bash
npm test
```
تختبر تسجيل الدخول، الصلاحيات، قاعدة الحد الأدنى، كشف التكرار، رفع الصور، الخطة الشهرية، والدورة الكاملة بين حسابات المؤسسات واعتماد الإدارة: الإرسال ← الإعادة ← التعديل ← الاعتماد للأنشطة والخطط والتقارير، مع التنبيهات والسجل الزمني وأكواد الاعتماد والتحقق منها، وإنشاء PDF. تحتاج قاعدة بيانات مهيأة، و Chrome لاختبار PDF.

## هيكل المشروع
```
src/
  server.js            نقطة التشغيل
  app.js               إعداد Express والمسارات
  config.js            الإعدادات من .env
  db/schema.sql        الجداول
  db/seed-data.js      المؤسسات (10) والمراكز (47) وأنواع الأنشطة
  db/init.js           تهيئة القاعدة
  middleware/auth.js   الجلسات (JWT في كوكي httpOnly) والصلاحيات
  routes/              auth · meta · activities · photos · users
public/
  index.html, login.html, css/app.css, js/app.js, img/ (الشعارات)
uploads/               صور التوثيق (يجب أخذ نسخة احتياطية منه مع القاعدة)
```

## واجهة البرمجة (API)
| الطريقة | المسار | الوصف |
|---|---|---|
| POST | `/api/auth/login` · `/logout` · `/password` | الدخول والخروج وتغيير كلمة المرور |
| GET | `/api/auth/me` | المستخدم الحالي |
| GET | `/api/meta` | المؤسسات والمراكز والأنواع والقواعد |
| GET | `/api/activities?from&to&inst&center` | الأنشطة (مقيّدة بمؤسسة المستخدم) |
| POST | `/api/activities/batch` | حفظ دفعة أنشطة مع الصور (multipart) |
| DELETE | `/api/activities/:id` | حذف (المدير أو من سجّله) |
| GET | `/api/photos/:id/thumb` · `/full` | الصور |
| GET | `/api/plans?from&to` | ملخص الخطط لكل مركز وشهر |
| GET/PUT | `/api/plans/:center/:month` | قراءة الخطة أو حفظها (`submit:true` للإرسال) |
| POST | `/api/plans/:id/review` | اعتماد أو إعادة للتعديل (للمدير) |
| POST | `/api/activities/review` | اعتماد أو إعادة أنشطة `{ids, action, note}` (للمدير) |
| PATCH | `/api/activities/:id` | تعديل نشاط غير معتمد (يعود للمراجعة) |
| GET | `/api/approvals` · `/api/approvals/timeline/:type/:id` | المهام والاعتمادات، والسجل الزمني |
| GET · POST | `/api/notifications` · `/api/notifications/read` | التنبيهات والعدادات |
| GET · POST · PUT | `/api/reports` · `/api/reports/:id` · `/api/reports/:id/review` | التقارير الرسمية واعتمادها |
| POST | `/api/exports/pdf` | تحويل مستند إلى PDF |
| GET | `/api/public/verify/:code` · `/verify/:code` | التحقق العام من كود الاعتماد (بدون دخول) |
| GET/POST/PATCH | `/api/users` | إدارة الحسابات (للمدير) |

كل طلب يغيّر بيانات يجب أن يحمل الترويسة `X-Requested-With: fetch` (حماية من CSRF).

## النشر على الإنترنت
- يصلح لأي استضافة Node (Render, Railway, VPS…) مع PostgreSQL مُدار (Neon, Supabase…) — اضبط `DATABASE_SSL=true` عند الحاجة.
- اضبط `NODE_ENV=production` و `JWT_SECRET` طويل وعشوائي، وشغّل خلف HTTPS.
- مجلد `uploads/` يجب أن يكون على قرص دائم (Volume). على الاستضافات التي تمسح القرص عند كل نشر، انقل الصور لخدمة تخزين مثل S3/Cloudflare R2.
- خذ نسخة احتياطية دورية: `pg_dump` للقاعدة + نسخ مجلد `uploads/`.
